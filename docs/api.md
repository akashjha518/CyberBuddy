# CyberBuddy API Documentation

CyberBuddy exposes a FastAPI REST API for message and URL analysis.

## Base URL

When running locally:

```text
http://127.0.0.1:8000
```

Interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

---

## GET `/health`

Checks whether the CyberBuddy API is running.

### Example

```http
GET /health
```

### Response

```json
{
  "status": "ok",
  "service": "CyberBuddy",
  "version": "0.1.0"
}
```

---

## POST `/api/analyze/message`

Analyzes a suspicious message.

### Request

```json
{
  "message": "URGENT! Your bank account will be blocked. Please provide your OTP immediately at https://example.com/login"
}
```

### Response

The response contains the deterministic analysis and, when Ollama is available, an AI-generated explanation.

Typical fields include:

```json
{
  "risk": "CRITICAL",
  "score": 95,
  "possible_attack": "Phishing",
  "indicators": [],
  "urls": [],
  "recommended_actions": [],
  "ai_explanation": "..."
}
```

The exact indicator and recommendation contents depend on the input.

### Validation

The `message` field:

- Is required
- Must contain at least one character
- Has a maximum length of 10,000 characters

Invalid requests return an HTTP 400/422 response depending on the validation or analysis error.

---

## POST `/api/analyze/url`

Analyzes a suspicious URL.

### Request

```json
{
  "url": "http://192.168.1.10/login"
}
```

### Example Result

```text
Risk: MEDIUM
Score: 40/100
Hostname: 192.168.1.10
Protocol: HTTP
```

Detected indicators can include:

- URL does not use HTTPS
- IP address used instead of a domain name
- Security-sensitive keyword detected

### Validation

The `url` field:

- Is required
- Must contain at least one character
- Has a maximum length of 2,048 characters

---

## AI Explanation Behavior

The AI explanation is generated by:

```text
CyberBuddy
    |
    v
Ollama
    |
    v
Gemma 3 4B
```

The AI receives the deterministic analysis rather than making an independent security decision.

If the Ollama request fails, the API still returns the deterministic analysis and the AI explanation is unavailable.

## Testing the API

Start the backend:

```bash
uvicorn backend.main:app --reload --port 8000
```

Then open:

```text
http://127.0.0.1:8000/docs
```

FastAPI's interactive documentation can be used to test all endpoints.
