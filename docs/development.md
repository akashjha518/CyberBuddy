# CyberBuddy Development Guide

## Development Environment

CyberBuddy was developed as a local Python application with a FastAPI backend and a browser-based frontend.

### Main Components

- Python
- FastAPI
- Pydantic
- JavaScript
- HTML
- CSS
- Ollama
- Gemma 3 4B
- Pytest

## Project Setup

Create a virtual environment:

```powershell
python -m venv .venv
```

Activate it on Windows:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```powershell
pip install -r requirements.txt
```

## AI Setup

Install Ollama and download Gemma:

```powershell
ollama pull gemma3:4b
```

Verify the model:

```powershell
ollama list
```

Optional direct test:

```powershell
ollama run gemma3:4b
```

## Running the Backend

From the project root:

```powershell
uvicorn backend.main:app --reload --port 8000
```

API:

```text
http://127.0.0.1:8000
```

Health check:

```text
http://127.0.0.1:8000/health
```

API documentation:

```text
http://127.0.0.1:8000/docs
```

## Running the Frontend

From the project root:

```powershell
python -m http.server 3000
```

Open:

```text
http://127.0.0.1:3000/frontend/index.html
```

## Development Principles

### Keep Security Logic Deterministic

Risk scoring and security indicators should be generated by deterministic code.

### Use AI as an Explanation Layer

Gemma should explain the supplied evidence rather than override the deterministic result.

### Fail Safely

If Ollama is unavailable, CyberBuddy should continue returning deterministic analysis.

### Avoid Sensitive Data

CyberBuddy should never request or encourage users to share:

- Passwords
- OTPs
- PINs
- API keys
- Authentication tokens
- Other secrets

## Suggested Development Workflow

1. Make a small change.
2. Run the relevant tests.
3. Run the full test suite.
4. Start the FastAPI backend.
5. Test the API.
6. Test the frontend.
7. Review the Git diff.
8. Commit the change.

Example:

```powershell
python -m pytest
git status
git diff
git add .
git commit -m "Describe the change"
```
